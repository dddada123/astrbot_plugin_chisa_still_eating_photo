# 🍳 千小妹后厨 - DLC 仓库管理工具

> 图形化 DLC 管理工具，用于将资源包上传至 GitHub Release，与 [astrbot_plugin_chisa_still_eating](https://github.com/dddada123/astrbot_plugin_chisa_still_eating) 插件无缝集成。

---

## 📦 快速开始（5 分钟）

### 1. 环境要求
- Windows 10/11（Python 3.8+）
- GitHub 账号

### 2. 准备 GitHub 仓库
1. 创建一个**公开仓库**（推荐）。
2. 在该仓库中**创建一个 Release**：
   - **Tag** 必须填写 **`Chisa_Dlc_Store`**（工具默认值，可自定义，但必须一致）。
   - 点击 **Publish release**。
3. 生成 **Personal Access Token (classic)**：
   - Settings → Developer settings → Personal access tokens → Tokens (classic)。
   - 勾选 **`repo`**（私有仓库）或 **`public_repo`**（公开仓库）。
   - 复制 Token（仅显示一次）。

### 3. 运行工具
- 双击 `千小妹后厨2.9.70.pyw` 启动。
- 首次运行自动检测依赖，按提示安装即可。
- 切换到 **“GitHub 同步”** 标签页，填写：
  - **仓库地址**：`https://github.com/用户名/仓库名` 或 `用户名/仓库名`
  - **Release Tag**：保持 `Chisa_Dlc_Store`
  - **Token**：粘贴刚才的 Token
- 点击 **“保存配置”**（可选）。

### 4. 创建并上传第一个 DLC
1. 切换到 **“打包与生成”** 标签页。
2. 选择分类、填写标题、作者，点击 **“映射新资源”** 添加图片。
3. 点击 **“锻造 DLC 安装包”** 生成本地 ZIP 和索引。
4. 回到 **“GitHub 同步”**，点击 **“🚀 开始同步”**（保持默认选项）。
5. 等待上传完成，您的 DLC 就上线了！

### 5. 在千小妹插件中使用
- 打开 AstrBot WebUI → **“千小妹商会”**。
- 点击 **“创意工坊”**，输入您的仓库地址，点击 **“连接并拉取目录”**。
- 即可浏览和下载您上传的 DLC。

## 📖 完整功能手册

### 一、工具简介
- ✅ 可视化创建 DLC 元数据（ID、标题、作者、封面、简介等）
- ✅ 自动打包 ZIP，计算 SHA256 校验
- ✅ 管理本地 `catalog.json`（增删改查、排序、筛选、拖拽）
- ✅ 与 GitHub Release 双向同步（上传/下载/删除）
- ✅ 支持官方商店与第三方创意工坊切换
- ✅ 多种上传策略（增量/覆盖/镜像/选择特定）
- ✅ 智能差异比对，可视化合并本地与云端
- ✅ 安全存储 Token（支持 keyring 加密）

### 二、界面功能详解

#### 2.1 打包与生成
- **元数据配置**：分类、编号、封面、标题、作者、简介，支持“同步标题到简介”。
- **资源装载区**：使用“映射新资源”添加图片，可指定目标文件夹（如 `food/common/`），支持干饭人语录。
- **锻造**：生成 ZIP 包，计算 SHA256，保存到 `releases/`，更新 `catalog.json`。
- **缩放**：可调整界面内容缩放比例。

#### 2.2 JSON 库管系统
- 表格显示所有 DLC，支持分类筛选、ID 排序。
- **拖拽排序**：在“全部”+“默认顺序”下可拖拽调整顺序。
- **编辑**：选中条目后在下方修改字段，点击“应用修改”保存。
- **删除**：可选择同时将本地文件移至回收站（需安装 send2trash）。
- **清理本地**：删除本地 ZIP 和封面，标记“已清理”，保留云端记录。
- **加载到打包器**：双击条目或点击按钮回填元数据，便于重新生成。

#### 2.3 GitHub 同步
| 模块 | 功能说明 |
|------|----------|
| 仓库配置 | 填写仓库地址、Release Tag、Token，支持加密存储。 |
| 商店元数据 | 填写商店名称、作者、简介，上传横幅图片（自动推送到仓库 `assets/`）。 |
| 上传策略 | Index（是否上传 `catalog.json`）、Covers（增量/覆盖/镜像）、Releases（增量/覆盖/镜像/选择特定）。 |
| 比对差异 | 对比本地与云端，列出差异项，可勾选并执行操作（上传/下载/删除/清理）。 |
| 开始同步 | 根据策略执行上传，实时显示进度和速度。 |

#### 2.4 云端管理
- 以颜色标签区分状态：🔵 仅云端（已清理）、🟢 双端齐全、🟠 状态交错、🔴 双端遗失。
- 支持快速刷新、深度比对（检查实际文件）。
- 操作：下载选中、智能合并、清理本地、全量下载、仅删云端文件、彻底下架。

#### 2.5 设置
- **环境依赖**：一键安装所有缺失库（PyGithub、requests、send2trash、keyring）。
- **安全凭证**：将 Token 迁移到操作系统密钥链（keyring）。
- **代理**：支持系统默认或自定义 HTTP 代理。

### 三、典型工作流程

#### 上传新 DLC
1. 准备图片 → 2. 打包与生成 → 3. GitHub 同步（增量）→ 4. 插件 WebUI 拉取目录。

#### 从云端恢复本地丢失的 DLC
1. 云端管理 → 深度比对 → 2. 选中“云端独有”或“缺失” → 3. 点击“下载选中项”或“智能合并同步”。

#### 清理本地空间，保留云端备份
1. 在库管或云端管理中选择 DLC → 2. 点击“清理本地” → 3. 本地文件删除并标记“已清理”，云端数据保留。

### 四、常见问题

**Q1：上传失败，提示 `'Repository' object has no attribute 'create_release'`**  
A：Token 权限不足，重新生成并勾选 `repo` 或 `public_repo`。

**Q2：Release 中看不到附件**  
A：检查 Tag 是否一致，Release 是否已发布（非 Draft）。

**Q3：封面无法加载**  
A：确保封面文件名与 DLC ID 一致，扩展名匹配，且已上传到 `covers/`。

**Q4：PyGithub 未安装**  
A：点击“GitHub 同步”页面的“点击安装 PyGithub”按钮，或手动 `pip install PyGithub`。

**Q5：如何切换官方/创意工坊？**  
A：在插件 WebUI 的“千小妹商会”页面，点击“千小妹严选”或“创意工坊”按钮。

**Q6：可以管理多个仓库吗？**  
A：可以，切换时自动加载对应缓存（历史记录最多 15 个）。

**Q7：自定义 Release Tag？**  
A：在工具中修改 Tag，并确保 GitHub Release 使用相同 Tag。
