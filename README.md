## 📦 快速开始：5 分钟上架第一个 DLC

### 1. 环境要求

- Windows 10 / 11
- Python 3.9+
- GitHub 账号

### 2. 准备 GitHub 仓库与 Token

1. 创建一个公开仓库，例如 `my_chisa_dlc_store`。
2. 在仓库中创建一个 Release：
   - Tag 保持默认的 `Chisa_Dlc_Store`，不要随意修改。
   - 点击 **Publish release** 正式发布，不要保留为 Draft。
3. 生成 Personal Access Token (classic)：
   - GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic)。
   - 公开仓库至少勾选 `public_repo`；需要操作私有仓库时勾选完整 `repo`。
   - Token 只显示一次，请妥善保存。

### 3. 配置工具

1. 双击 `千小妹后厨3.0.18β.pyw` 启动。首次运行会检查缺失依赖，可在“设置”中一键安装。
2. 打开 **GitHub 同步**：
   - 仓库地址填写 `https://github.com/用户名/仓库名` 或 `用户名/仓库名`。
   - Release Tag 保持 `Chisa_Dlc_Store`。
   - 填写 GitHub Token。
   - 分别保存仓库地址和 Token。
3. 建议安装 `keyring` 并点击“升级为加密存储”，避免 Token 明文留盘。

> 离开 GitHub 同步页时，工具会自动静默保存发生变化的仓库配置。

### 4. 创建并上传 DLC

1. 打开 **打包生成**，选择分类、确认自动/手动编号，填写标题、作者和简介。
2. 点击“映射新资源”，加入图片并设置 ZIP 内目标目录。
3. 点击“锻造 DLC 安装包”，工具会生成 ZIP、计算 SHA-256、制作封面并更新 `index/catalog.json`。
4. 可在 GitHub 同步页配置商店名称、作者、简介和横幅，再执行全量推送装潢。
5. 点击“开始同步”，按所选策略上传 Index、Covers 和 Release 文件。

### 5. 玩家使用 DLC

1. 打开 AstrBot WebUI → 千小妹商会 → 创意工坊。
2. 粘贴你的仓库地址并点击“连接并拉取目录”。
3. 玩家可以浏览、下载商品，并将仓库收藏到“我的工坊书架”。

## 🎨 快速开始：发布第一个皮肤

### 1. 打开主题工坊

进入 **主题工坊 → 制作发布**，依次填写：

- **皮肤编号**：格式必须为 `sk` 加至少四位数字，例如 `sk0006`。编号可编辑；填写已有编号代表更新该商品。
- **皮肤名称、作者与商品简介**：由本地表单控制；简介会同时写入完整皮肤配置与商店索引。
- **皮肤类型**：`glass` 为毛玻璃主题，`solid` 为实色主题。
- **背景图**：JPG、PNG 或 WebP，可选；新建草稿不选择背景时生成纯色皮肤，读取已有皮肤后默认保持原背景。
- **切换台词**：一句一行，玩家切换主题时随机显示。
- **强调色与兜底背景色**：用于给 AI 提供基础风格方向。

### 2. 让 AI 生成皮肤 JSON

1. 点击“复制 AI 提示词”。
2. 将提示词与准备使用的原始背景图一起发给支持识图的模型。
3. DeepSeek Flash 网页版已经足够完成这项工作。
4. 将 AI 输出的 JSON 粘贴回“皮肤样式 JSON”。
5. 点击“校验 JSON”。

工具会检查：

- JSON 只能包含规定的 `vars` 结构。
- 15 个主题变量必须完整，包括 `--primary-contrast`。
- 颜色格式必须合法。
- 文字、背景和高亮按钮组合必须满足最低 4.5:1 对比度。
- 不允许渐变、图片地址、CSS 变量引用或其他越界样式。

### 3. 上传皮肤

点击 **原子覆盖云端**，工具会尝试把配置、可选背景和索引作为一次提交写入：

1. 校验 `skNNNN` 编号和皮肤 JSON。
2. 上传 `skin/skNNNN.json`。
3. 新建或替换背景时上传对应图片；保持背景时沿用原引用。
4. 安全合并并更新 `skin/index.json`。
5. 索引条目同时写入 `desc` 和仅含 `--primary` / `--bg` 的预览 `vars`，供 4.2.3 卡片展示简介与印象色。
6. 如果编号已存在，必须先从本地或云端读取；工具按同 ID 原位更新，不影响其他皮肤。

### 4. 在插件中检查真实效果

打包工具目前没有内置 AstrBot WebUI 预览，因此上传成功不代表最终视觉已经完成。建议使用下面的真实环境检查流程：

1. **首次上传后先不要关闭打包工具。** 保留当前编号、背景图、名称和其他表单内容。
2. 在千小妹还在吃 WebUI 的皮肤工坊中，把自己的 GitHub 仓库加入第三方皮肤源。
3. 刷新皮肤源，下载刚上传的皮肤并实际应用。
4. 检查背景明暗区域、面板透明度、文字可读性、按钮高亮和整体色彩是否协调。
5. 如果效果不满意，截图保存当前 WebUI 效果。

> 3.0.18β 读取现有皮肤后，背景默认为“保持”，无需重新选择原图；只有明确点击“清除”才移除配置与索引中的背景引用。旧背景二进制不会自动删除。

## ✏️ 3.0.18β：读取和编辑现有皮肤

### 从本地读取

1. 在“制作发布”点击 **打开本地皮肤 JSON**，或在“本地索引”选中商品后点击 **载入选中配置到编辑器**。
2. 工具载入同 ID 配置、名称、作者、简介、类型、台词、`vars` 与背景引用，并锁定 ID。
3. 可以粘贴完整 `vars`，也可以只粘贴需要修改的变量；局部内容会叠加到原配置。
4. 点击 **保存 / 同 ID 覆盖本地**。原配置与索引会先备份到 `skin/backups/`，未知 JSON 字段和索引顺序保持不变。

### 从 GitHub 读取并原子覆盖

1. 配置好仓库和 Token，在“云端皮肤”深度刷新后选择一项，点击 **载入选中到编辑器**；也可在制作页输入编号后点击 **读取云端当前编号**。
2. 工具在同一个分支头读取 `skin/index.json` 与对应配置，并缓存到本地 `skin/`。
3. 修改需要的字段后点击 **原子覆盖云端**。配置、可选新背景和索引会作为一个 Git commit 提交。
4. 如果分支在读取后被其他操作更新，工具会中止并要求重新读取，不会强制覆盖。

读取现有 14 变量皮肤时可以保持缺少 `--primary-contrast` 的历史结构；新建皮肤仍要求完整 15 变量。背景有明确的“保持 / 替换 / 移除”状态，空文件选择不再等于删除。

### 原子覆盖失败时：只更新商店信息的备用流程

如果 **原子覆盖云端** 因 GitHub API、网络状态或远端文件读取问题失败，但本次只需要更新商店卡片上的名称、作者、简介或印象色，可以使用下面的备用链路：

1. 在“制作发布”完成修改并点击 **校验 JSON**。
2. 点击 **保存 / 同 ID 覆盖本地**，让本地 `skin/skNNNN.json` 与 `skin/index.json` 先保存当前内容；工具会在覆盖前创建备份。
3. 切换到 **本地索引**，选中同一个 `skNNNN` 商品，确认名称、作者、简介和印象色正确。
4. 点击 **仅同步选中商品**。工具会读取最新云端索引，只替换该 ID 的商品条目，不改其他商品，也不改变条目顺序。
5. 回到插件刷新皮肤来源，检查商店卡片信息。

> **适用范围：**这条备用链路只更新云端 `skin/index.json` 中的选中商品信息，不会上传 `skin/skNNNN.json` 或背景图片。若修改的是实际主题 `vars`、台词、类型或背景，仍需重新读取云端编号后重试 **原子覆盖云端**，或在确认路径无误后单独维护对应云端文件。

### 独立编辑皮肤商品列表

“本地索引”现在是皮肤商品列表编辑器：

- 列表展示名称、作者、简介、印象色、配置、背景与毛玻璃状态。
- **保存商品信息**只改本地 `skin/index.json`，不会改完整皮肤配置。
- **仅同步选中商品**会读取最新云端索引，只原位替换该 ID 的索引条目；不会上传配置或背景，也不会覆盖其他商品。
- **上传完整本地索引**仍保留给明确需要整体覆盖的场景。

### 一键同步云端预览与简介

“云端皮肤”的 **一键同步预览与简介** 会：

1. 固定当前分支头并逐项读取索引指向的完整皮肤 JSON。
2. 从配置 `vars` 提取 `--primary` 与 `--bg`，并读取 `desc`。
3. 回填每个索引条目的预览 `vars` 与商品简介，保留条目未知字段和原顺序。
4. 用一次 Git 提交更新云端 `skin/index.json`，再缓存配置和索引到本地。
5. 输出更新、跳过、失败数量；任一配置缺失或颜色非法时整体中止。

该扩展继续使用 `schema_version: 1`。旧仓库无需补字段，4.2.3 会显示新字段；旧插件会忽略它们。

## 🤖 AI 首稿不理想时怎么优化

当前内置提示词能够保证 JSON 结构和基础对比度，但无法完全理解每张背景图的构图、人物位置、最亮区域和最暗区域。因此，AI 第一次生成的版本大概率只能作为初稿，实际放入 WebUI 后可能不够协调。

这不是必须换模型才能解决的问题。DeepSeek Flash 网页版具备足够的识图和配色调整能力，关键是让它同时看到：

- 原始背景图。
- 皮肤在 WebUI 中的实际效果截图。
- 当前使用的样式 JSON。
- 你认为不好看的具体位置。

可以这样继续要求 AI：

```text
这是原始背景图、当前 WebUI 效果截图和正在使用的皮肤 vars JSON。
请观察人物、背景最亮/最暗区域和面板覆盖后的文字可读性，优化面板透明度、卡片层次、文字颜色、弱化文字、边框、遮罩和强调色。
保留现有 JSON 结构与全部 15 个变量，确保六组文字对比度均不低于 4.5:1。
不要输出解释，只输出最终 JSON。
```

### 推荐的二次迭代流程

1. 第一次上传后，在插件内下载并查看实际效果。
2. 将原图、实际截图和当前 JSON 发给 DeepSeek Flash。
3. 让 AI 根据真实效果重新优化，而不是只根据主题名称猜颜色。
4. 回到仍然打开的打包工具，将优化后的 JSON 填回样式框。
5. 皮肤编号继续填写原来的不满意编号，例如仍使用 `sk0006`。
6. 保持或重新选择原背景图，点击校验并再次上传。
7. 工具会覆盖更新同编号商品；回到插件刷新并点击“下载 / 更新”检查新版效果。
8. 如果仍不满意，可以继续使用同一编号重复优化，不需要制造 `sk0007`、`sk0008` 等重复商品。

## 📖 完整功能手册

### 一、核心能力

- 可视化创建 DLC 元数据：编号、标题、作者、封面和简介。
- 一键生成 DLC ZIP 和 SHA-256，与插件端安全校验配套。
- 本地 `catalog.json` 增删改查、筛选、排序、清理和回填打包器。
- GitHub Index、Covers、Release、商店元数据双向同步。
- 增量、覆盖和镜像上传策略。
- 云端管理中精准上传、下载、合并、清理和下架选中 DLC。
- 皮肤配置制作、15 变量新建校验、14/15 变量旧配置读取、背景上传和 `skin/index.json` 自动维护。
- 本地 / GitHub 皮肤读取、局部 `vars` 修改、未知字段保留及同 ID 原子覆盖。
- 皮肤商品简介与两色印象预览写入、云端批量回填和 4.2.3 卡片兼容。
- 本地皮肤商品列表排序、简介编辑、选中条目单独同步、完整索引拉取和上传。
- 云端皮肤完整性检查、孤立文件统计和带解锁保护的原子下架。
- Token 可使用 keyring 系统级加密存储。

### 二、六大页签

#### 2.1 打包生成

- 选择食品、饮品、导游表情、干饭人、黑暗料理或专属大厨分类。
- 支持自动/手动编号、封面映射、标题、作者、简介和图库数量统计。
- 映射资源到 ZIP 内指定目录；支持干饭人专属语录。
- 锻造后自动更新本地目录并计算校验值。

#### 2.2 商品目录

- 表格展示全部 DLC，支持分类筛选和 ID 排序。
- “全部 + 默认顺序”下可拖拽商品顺序，并同步到云端。
- 支持编辑、删除、回填打包器和仅清理本地文件。
- 本地文件清理后保留云端记录和“已清理”状态。

#### 2.3 GitHub 同步

| 模块 | 功能 |
| --- | --- |
| 仓库配置 | 仓库地址、Release Tag、Token 保存及 keyring 加密 |
| 商店装潢 | 名称、作者、简介和横幅上传到 `Chisa_DLC_Metadata.json` 与 `assets/` |
| 上传策略 | Index 覆盖；Covers / Releases 增量、覆盖或镜像同步 |
| 差异比对 | 检查本地与云端差异并选择处理范围 |
| 开始同步 | 实时显示上传进度、速度和执行日志 |

#### 2.4 主题工坊

**制作发布**

- 编辑 `skNNNN` 编号、名称、作者、商品简介、类型、背景和切换台词。
- 打开本地 JSON 或按编号读取云端配置；已读取 ID 锁定，背景默认保持。
- 复制带本地上下文的 AI 提示词；已读取配置支持完整或局部 `vars`。
- 新建时校验完整 15 变量；读取历史配置时兼容 14 变量并继续检查可用对比组合。
- 本地同 ID 保存或用一次 Git commit 原子更新云端配置、可选背景和索引。

**本地索引**

- 以商品列表形式管理本地 `skin/index.json`，查看简介和印象色。
- 编辑名称、作者、简介和毛玻璃状态，上移/下移商品顺序。
- 将选中完整配置载入编辑器，或只把选中商品信息同步到最新云端索引。
- 从 GitHub 拉取完整索引或明确上传完整本地索引。

**云端皮肤**

- 深度读取云端索引、配置和背景状态，并可把选中配置下载到编辑器。
- 一键读取全部云端配置，将 `--primary` / `--bg` 印象色和 `desc` 简介回填索引。
- 显示缺失配置、缺失背景及孤立文件数量。
- 强制下架需要先解锁并校验本地/云端索引一致；目标配置、未共享背景和索引条目通过一次 Git commit 原子删除。
- 精确删除目标配置和背景，不影响其他编号。

#### 2.5 云端管理

- 颜色状态区分仅云端、双端完整、状态交错、文件缺失、死链和本地独有。
- 提供快速刷新与逐项检查真实文件的深度比对。
- 支持下载选中项、上传选中项、智能合并、清理、全量下载、仅删云端文件及彻底下架。
- 下载或合并恢复本地文件后，状态会自动更新。

| 场景 | 操作 |

| 上架新 DLC | 准备图片 → 打包生成 → 锻造 → GitHub 同步 → 玩家刷新货架 |

| 更换商店门面 | GitHub 同步修改装潢 → 全量推送装潢 |
| 上架新皮肤 | 制作发布 → AI 生成 JSON → 校验 → 上传 → 插件添加皮肤源并更新 |
| 优化已有皮肤 | 插件截图 → AI 看原图和截图优化 → 使用原 `skNNNN` 原子覆盖 → 插件下载/更新 |
| 仅更新皮肤商店信息 | 保存 / 同 ID 覆盖本地 → 本地索引选中商品 → 仅同步选中商品 |
| 调整皮肤顺序 | 本地索引移动条目 → 明确上传完整本地索引 |
| 下架皮肤 | 云端皮肤深度刷新 → 确认索引一致 → 解锁并强制下架 |

## ❓ 常见问题

**Q1：上传失败，提示 Repository 对象没有 create_release？**

通常是 PyGithub 版本过旧或 Token 权限不足。请在“设置”重装依赖，并确认 Token 具有 `repo` 或 `public_repo` 权限。

**Q2：玩家端看不到 DLC 或下载 404？**

检查 Release 是否已 Publish、Tag 是否为 `Chisa_Dlc_Store`、仓库是否存在 `index/catalog.json`，以及同步时是否上传了 Index。

**Q3：商店名或横幅没有更新？**

确认已经推送 `Chisa_DLC_Metadata.json` 和 `assets/banner.*`，再让玩家刷新货架。

**Q4：DLC 封面无法加载？**

封面文件名必须与 DLC ID 一致，例如 `fd0001.png`，并上传到 `covers/`。

**Q5：误清理本地 DLC 怎么办？**

云端文件仍在时，可在云端管理中下载选中项恢复。

**Q6：可以管理多个仓库吗？**

可以。修改并保存仓库地址后即可切换，各仓库缓存相互独立。操作前注意确认当前仓库。

**Q7：能自定义 Release Tag 吗？**

工具允许修改，但插件端默认按 `Chisa_Dlc_Store` 寻址。没有同步修改插件协议时不要更换。

**Q8：为什么 AI 第一次生成的皮肤不好看？**

提示词只能约束结构和基础对比度，不能代替真实 WebUI 构图判断。请上传后在插件中预览，再把原图、效果截图和 JSON 一起发给 DeepSeek Flash 优化。

**Q9：怎么覆盖不满意的皮肤？**

优先在“云端皮肤”选中目标并载入编辑器，或点击“读取云端当前编号”。修改简介、表单或完整/局部 `vars` 后校验并原子上传。读取会话锁定原 ID，避免误建重复商品。

**Q10：打包器可以直接预览皮肤吗？**

当前版本没有本地 AstrBot WebUI 预览。请把自己的仓库加入插件第三方皮肤源，通过真实页面检查效果。

**Q11：更新皮肤时不选择背景会怎样？**

新建草稿不选背景表示无背景主题。读取已有皮肤后不选新文件表示保持原背景；点击“清除”才会移除背景引用，旧背景二进制仍保留在仓库以避免误删共享资源。

**Q12：皮肤上传后插件里还是旧效果？**

在插件皮肤工坊刷新来源，然后对该皮肤点击“下载 / 更新”。必要时使用重新下载背景功能清理旧缓存。

**Q13：为什么云端卡片还没有简介或自己的色块？**

先使用 3.0.18β 的“一键同步预览与简介”补齐远端 `skin/index.json`，再将插件更新到 4.2.3。旧插件会在后端丢弃索引扩展字段，因此只改仓库不能让 4.2.2 显示新内容。

**Q14：原子覆盖云端失败，但我只想更新商店名称、简介或印象色怎么办？**

先点击 **保存 / 同 ID 覆盖本地**，再到 **本地索引** 选中该商品并点击 **仅同步选中商品**。这会安全更新该 ID 的云端索引条目，但不会上传完整皮肤 JSON 或背景；涉及实际主题样式和背景时仍需重新执行原子覆盖。
