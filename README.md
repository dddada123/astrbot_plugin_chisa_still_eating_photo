## 📦 快速开始：5 分钟上架第一个 DLC

### 1. 环境要求

- Windows 10 / 11
- Python 3.9+
- GitHub 账号

### 2. 准备 GitHub 仓库与 Token

1. 创建一个公开仓库，例如 `my_chisa_dlc_store`。
2. 在仓库中创建一个 Release：
   - Tag 保持默认的 `Chisa_Dlc_Store`，不要随意修改。
   - 点击 **Publish release** 正式发布，不要保留为 Draft。
3. 生成 Personal Access Token (classic)：
   - GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic)。
   - 公开仓库至少勾选 `public_repo`；需要操作私有仓库时勾选完整 `repo`。
   - Token 只显示一次，请妥善保存。

### 3. 配置工具

1. 双击 `Chisa_kitchen_manager_3.0.17.pyw` 启动。首次运行会检查缺失依赖，可在“设置”中一键安装。
2. 打开 **GitHub 同步**：
   - 仓库地址填写 `https://github.com/用户名/仓库名` 或 `用户名/仓库名`。
   - Release Tag 保持 `Chisa_Dlc_Store`。
   - 填写 GitHub Token。
   - 分别保存仓库地址和 Token。
3. 建议安装 `keyring` 并点击“升级为加密存储”，避免 Token 明文留盘。

> 离开 GitHub 同步页时，工具会自动静默保存发生变化的仓库配置。

### 4. 创建并上传 DLC

1. 打开 **打包生成**，选择分类、确认自动/手动编号，填写标题、作者和简介。
2. 点击“映射新资源”，加入图片并设置 ZIP 内目标目录。
3. 点击“锻造 DLC 安装包”，工具会生成 ZIP、计算 SHA-256、制作封面并更新 `index/catalog.json`。
4. 可在 GitHub 同步页配置商店名称、作者、简介和横幅，再执行全量推送装潢。
5. 点击“开始同步”，按所选策略上传 Index、Covers 和 Release 文件。

### 5. 玩家使用 DLC

1. 打开 AstrBot WebUI → 千小妹商会 → 创意工坊。
2. 粘贴你的仓库地址并点击“连接并拉取目录”。
3. 玩家可以浏览、下载商品，并将仓库收藏到“我的工坊书架”。

## 🎨 快速开始：发布第一个皮肤

### 1. 打开主题工坊

进入 **主题工坊 → 制作发布**，依次填写：

- **皮肤编号**：格式必须为 `sk` 加至少四位数字，例如 `sk0006`。编号可编辑；填写已有编号代表更新该商品。
- **皮肤名称与作者**：由本地表单控制，不需要让 AI 生成。
- **皮肤类型**：`glass` 为毛玻璃主题，`solid` 为实色主题。
- **背景图**：JPG、PNG 或 WebP，可选；不选择背景时会生成纯色皮肤。
- **切换台词**：一句一行，玩家切换主题时随机显示。
- **强调色与兜底背景色**：用于给 AI 提供基础风格方向。

### 2. 让 AI 生成皮肤 JSON

1. 点击“复制 AI 提示词”。
2. 将提示词与准备使用的原始背景图一起发给支持识图的模型。
3. DeepSeek Flash 网页版已经足够完成这项工作。
4. 将 AI 输出的 JSON 粘贴回“皮肤样式 JSON”。
5. 点击“校验 JSON”。

工具会检查：

- JSON 只能包含规定的 `vars` 结构。
- 15 个主题变量必须完整，包括 `--primary-contrast`。
- 颜色格式必须合法。
- 文字、背景和高亮按钮组合必须满足最低 4.5:1 对比度。
- 不允许渐变、图片地址、CSS 变量引用或其他越界样式。

### 3. 上传皮肤

点击“上传皮肤（配置 + 背景 + 更新索引）”，工具会：

1. 校验 `skNNNN` 编号和皮肤 JSON。
2. 上传 `skin/skNNNN.json`。
3. 上传对应背景图。
4. 安全合并并更新 `skin/index.json`。
5. 如果编号已存在，明确询问后更新该编号的配置、背景和索引，不影响其他皮肤。

### 4. 在插件中检查真实效果

打包工具目前没有内置 AstrBot WebUI 预览，因此上传成功不代表最终视觉已经完成。建议使用下面的真实环境检查流程：

1. **首次上传后先不要关闭打包工具。** 保留当前编号、背景图、名称和其他表单内容。
2. 在千小妹还在吃 WebUI 的皮肤工坊中，把自己的 GitHub 仓库加入第三方皮肤源。
3. 刷新皮肤源，下载刚上传的皮肤并实际应用。
4. 检查背景明暗区域、面板透明度、文字可读性、按钮高亮和整体色彩是否协调。
5. 如果效果不满意，截图保存当前 WebUI 效果。

> 更新毛玻璃皮肤时，请保持原背景仍被选中，或者重新选择同一张背景图。若清空背景后覆盖上传，该编号会被当作无背景皮肤处理，并移除原背景引用。

## 🤖 AI 首稿不理想时怎么优化

当前内置提示词能够保证 JSON 结构和基础对比度，但无法完全理解每张背景图的构图、人物位置、最亮区域和最暗区域。因此，AI 第一次生成的版本大概率只能作为初稿，实际放入 WebUI 后可能不够协调。

这不是必须换模型才能解决的问题。DeepSeek Flash 网页版具备足够的识图和配色调整能力，关键是让它同时看到：

- 原始背景图。
- 皮肤在 WebUI 中的实际效果截图。
- 当前使用的样式 JSON。
- 你认为不好看的具体位置。

可以这样继续要求 AI：

```text
这是原始背景图、当前 WebUI 效果截图和正在使用的皮肤 vars JSON。
请观察人物、背景最亮/最暗区域和面板覆盖后的文字可读性，优化面板透明度、卡片层次、文字颜色、弱化文字、边框、遮罩和强调色。
保留现有 JSON 结构与全部 15 个变量，确保六组文字对比度均不低于 4.5:1。
不要输出解释，只输出最终 JSON。
```

### 推荐的二次迭代流程

1. 第一次上传后，在插件内下载并查看实际效果。
2. 将原图、实际截图和当前 JSON 发给 DeepSeek Flash。
3. 让 AI 根据真实效果重新优化，而不是只根据主题名称猜颜色。
4. 回到仍然打开的打包工具，将优化后的 JSON 填回样式框。
5. 皮肤编号继续填写原来的不满意编号，例如仍使用 `sk0006`。
6. 保持或重新选择原背景图，点击校验并再次上传。
7. 工具会覆盖更新同编号商品；回到插件刷新并点击“下载 / 更新”检查新版效果。
8. 如果仍不满意，可以继续使用同一编号重复优化，不需要制造 `sk0007`、`sk0008` 等重复商品。

## 📖 完整功能手册

### 一、核心能力

- 可视化创建 DLC 元数据：编号、标题、作者、封面和简介。
- 一键生成 DLC ZIP 和 SHA-256，与插件端安全校验配套。
- 本地 `catalog.json` 增删改查、筛选、排序、清理和回填打包器。
- GitHub Index、Covers、Release、商店元数据双向同步。
- 增量、覆盖和镜像上传策略。
- 云端管理中精准上传、下载、合并、清理和下架选中 DLC。
- 皮肤配置制作、15 变量 JSON 校验、背景上传和 `skin/index.json` 自动维护。
- 可编辑皮肤编号及同编号更新覆盖。
- 本地皮肤索引排序、元数据编辑、拉取和上传。
- 云端皮肤完整性检查、孤立文件统计和带解锁保护的精确下架。
- Token 可使用 keyring 系统级加密存储。

### 二、六大页签

#### 2.1 打包生成

- 选择食品、饮品、导游表情、干饭人、黑暗料理或专属大厨分类。
- 支持自动/手动编号、封面映射、标题、作者、简介和图库数量统计。
- 映射资源到 ZIP 内指定目录；支持干饭人专属语录。
- 锻造后自动更新本地目录并计算校验值。

#### 2.2 商品目录

- 表格展示全部 DLC，支持分类筛选和 ID 排序。
- “全部 + 默认顺序”下可拖拽商品顺序，并同步到云端。
- 支持编辑、删除、回填打包器和仅清理本地文件。
- 本地文件清理后保留云端记录和“已清理”状态。

#### 2.3 GitHub 同步

| 模块 | 功能 |
| --- | --- |
| 仓库配置 | 仓库地址、Release Tag、Token 保存及 keyring 加密 |
| 商店装潢 | 名称、作者、简介和横幅上传到 `Chisa_DLC_Metadata.json` 与 `assets/` |
| 上传策略 | Index 覆盖；Covers / Releases 增量、覆盖或镜像同步 |
| 差异比对 | 检查本地与云端差异并选择处理范围 |
| 开始同步 | 实时显示上传进度、速度和执行日志 |

#### 2.4 主题工坊

**制作发布**

- 编辑 `skNNNN` 编号、名称、作者、类型、背景和切换台词。
- 复制带本地上下文的 AI 提示词。
- 校验完整 15 变量 JSON 和 WCAG 文字对比度。
- 创建新皮肤或按已有编号更新配置、背景和索引。

**本地索引**

- 管理本地 `skin/index.json`。
- 编辑名称、作者和毛玻璃状态。
- 上移/下移皮肤商品顺序。
- 从 GitHub 拉取索引或上传本地索引。

**云端皮肤**

- 深度读取云端索引、配置和背景状态。
- 显示缺失配置、缺失背景及孤立文件数量。
- 强制下架需要先解锁，并在执行前校验本地与云端索引一致性。
- 精确删除目标配置和背景，不影响其他编号。

#### 2.5 云端管理

- 颜色状态区分仅云端、双端完整、状态交错、文件缺失、死链和本地独有。
- 提供快速刷新与逐项检查真实文件的深度比对。
- 支持下载选中项、上传选中项、智能合并、清理、全量下载、仅删云端文件及彻底下架。
- 下载或合并恢复本地文件后，状态会自动更新。

## 🔄 典型工作流程

| 场景 | 操作 |
| --- | --- |
| 上架新 DLC | 准备图片 → 打包生成 → 锻造 → GitHub 同步 → 玩家刷新货架 |
| 更新已有 DLC | 商品目录回填 → 换图重锻造 → 云端管理上传选中项 → 同步 Index |

## ❓ 常见问题

**Q1：上传失败，提示 Repository 对象没有 create_release？**

通常是 PyGithub 版本过旧或 Token 权限不足。请在“设置”重装依赖，并确认 Token 具有 `repo` 或 `public_repo` 权限。

**Q2：玩家端看不到 DLC 或下载 404？**

检查 Release 是否已 Publish、Tag 是否为 `Chisa_Dlc_Store`、仓库是否存在 `index/catalog.json`，以及同步时是否上传了 Index。

**Q3：商店名或横幅没有更新？**

确认已经推送 `Chisa_DLC_Metadata.json` 和 `assets/banner.*`，再让玩家刷新货架。

**Q4：DLC 封面无法加载？**

封面文件名必须与 DLC ID 一致，例如 `fd0001.png`，并上传到 `covers/`。

**Q5：误清理本地 DLC 怎么办？**

云端文件仍在时，可在云端管理中下载选中项恢复。

**Q6：可以管理多个仓库吗？**

可以。修改并保存仓库地址后即可切换，各仓库缓存相互独立。操作前注意确认当前仓库。

**Q7：能自定义 Release Tag 吗？**

工具允许修改，但插件端默认按 `Chisa_Dlc_Store` 寻址。没有同步修改插件协议时不要更换。

**Q8：为什么 AI 第一次生成的皮肤不好看？**

提示词只能约束结构和基础对比度，不能代替真实 WebUI 构图判断。请上传后在插件中预览，再把原图、效果截图和 JSON 一起发给 DeepSeek Flash 优化。

**Q9：怎么覆盖不满意的皮肤？**

在制作发布页填写原来的 `skNNNN`，保持或重新选择背景，粘贴新版 JSON 后校验并上传。工具确认后会更新该编号，而不是创建重复商品。

**Q10：打包器可以直接预览皮肤吗？**

当前版本没有本地 AstrBot WebUI 预览。请把自己的仓库加入插件第三方皮肤源，通过真实页面检查效果。

**Q11：更新皮肤时不选择背景会怎样？**

不选背景表示发布无背景主题，并会移除该编号原来的背景引用。只想改配色时请保留或重新选择原图。

**Q12：皮肤上传后插件里还是旧效果？**

在插件皮肤工坊刷新来源，然后对该皮肤点击“下载 / 更新”。必要时使用重新下载背景功能清理旧缓存。
