## 📦 快速开始（5 分钟上架你的第一个图包）

### 1. 环境要求
- Windows 10 / 11（Python 3.9+）
- GitHub 账号

### 2. 准备 GitHub 仓库与 Token
1. 创建一个**公开仓库**（仓库名随意，例如 `my_chisa_dlc_store`）。
2. 在该仓库中创建一个 **Release**：
   - **Tag 请保持默认的 `Chisa_Dlc_Store` 不要改动**！插件端按此 Tag 寻址下载商品包，自定义 Tag 会导致玩家端下载 404。
   - 点击 **Publish release** 发布（不要留 Draft）。
3. 生成 **Personal Access Token (classic)**：
   - GitHub → Settings → Developer settings → Personal access tokens → **Tokens (classic)**。
   - 勾选 **`repo`**（私有仓库需完整 repo 权限；公开仓库 `public_repo` 即可）。
   - 复制 Token（仅显示一次）。

### 3. 运行工具并完成配置
1. 双击 `千小妹后厨2.9.72.pyw` 启动。首次运行会自动检测缺失依赖，按提示一键安装即可。
2. 切换到 **「GitHub 同步」** 标签页，填写：
   - **仓库地址**：`https://github.com/用户名/仓库名`（也支持 `用户名/仓库名` 简写）→ 点击 **「💾 保存仓库地址」**
   - **Release Tag**：保持 `Chisa_Dlc_Store`
   - **GitHub Token**：粘贴 Token → 点击 **「💾 保存 Token」**（建议随后点击 **「🔐 升级为加密存储」** 将 Token 迁入系统密钥链，明文不留盘）

> 💡 小贴士：改完配置忘记点保存也没关系——**离开 GitHub 同步页签时会自动静默保存**。

### 4. 创建并上传第一个 DLC
1. 切换到 **「打包与生成」** 标签页：选择分类（食品/饮品/干饭人…）、填写标题与作者、点击 **「映射新资源」** 添加图片。
2. 点击 **「锻造 DLC 安装包」**——自动打包 ZIP、计算 SHA-256、生成封面与本地索引。
3. （可选）在 **「商店元数据装潢」** 区填写商店名称/作者/简介、选择横幅海报，点击 **「🚀 全量推送装潢」**——玩家看到的就是你的店铺门面！
4. 回到 **「GitHub 同步」**，点击 **「🚀 开始同步」**（保持默认策略），等待上传完成。

### 5. 玩家如何使用你的作品
- 玩家打开 AstrBot WebUI → **「千小妹商会」** → **「创意工坊」**。
- 粘贴你的仓库地址，点击 **「连接并拉取目录」**——货架、橱窗、横幅全自动加载。
- 从此你的仓库地址会被玩家收藏进 **「我的工坊书架」**，以后点击书签即可一键直达！

## 📖 完整功能手册

### 一、核心能力一览
- ✅ 可视化创建 DLC 元数据（自动编号、标题、作者、封面、简介）
- ✅ 一键打包 ZIP + SHA-256 校验值计算，与插件端防投毒校验配套
- ✅ 本地 `catalog.json` 库管理（增删改查、筛选、拖拽排序、批量清理）
- ✅ 与 GitHub 双向同步：目录 Index、封面 Covers、Release 压缩包、商店元数据
- ✅ 多种上传策略：增量（只传新增）/ 覆盖已有文件 / 镜像同步（高风险）
- ✅ **⬆️ 上传选中项**：在云端管理列表勾选任意 DLC，把本地版本精准覆盖上传到云端
- ✅ 智能差异比对与可视化合并（深度比对会逐一核对云端真实文件）
- ✅ 本地空间清理：ZIP/封面进回收站、打「已清理」标，云端永不下架
- ✅ Token 安全存储（keyring 系统级加密，明文零残留）

### 二、五大页签详解

#### 2.1 打包与生成
- **元数据配置**：分类、自动/手动编号、封面映射、标题、作者、简介，支持「同步标题到简介」。
- **资源装载区**：「映射新资源」添加图片并指定目标文件夹（如 `food/common/`），支持干饭人专属截胡语录。
- **锻造**：生成 ZIP 包并计算 SHA-256，存入 `releases/`，同步更新 `index/catalog.json`。

#### 2.2 JSON 库管系统
- 表格展示全部 DLC，支持分类筛选、ID 排序；「全部 + 默认顺序」下可**拖拽调整商品上架顺序**（可通过「同步本地排序至云端」推送）。
- **编辑**：选中条目修改字段后「应用修改」；**删除**：可选将本地文件移入回收站（需 send2trash）。
- **清理本地**：删除本地 ZIP 与封面并打「已清理」标记，云端记录完整保留——释放硬盘空间，商品照常销售。
- **加载到打包器**：双击条目回填元数据，改图重发一气呵成。

#### 2.3 GitHub 同步
| 模块 | 功能说明 |
|------|----------|
| 仓库配置 | 仓库地址、Release Tag、Token，独立的「保存仓库地址 / 保存 Token」按钮 + 页签切换自动保存，Token 支持 keyring 加密存储 |
| 商店元数据装潢 | 商店名称、作者署名、简介、横幅海报（推送至仓库 `Chisa_DLC_Metadata.json` 与 `assets/`）——玩家端创意工坊的店铺门面就靠它 |
| 上传策略 | Index（是否覆盖云端 `catalog.json`）、Covers（增量/覆盖/镜像）、Releases（增量/覆盖/镜像） |
| 比对差异 | 本地与云端逐项比对，差异可视化列出，支持勾选批量处理 |
| 开始同步 | 按策略执行上传，实时进度条 + 上传速度显示 |

#### 2.4 云端管理
- 基于**颜色标签**的仓库全景：🔵 仅云端存储（本地已清理）/ 🟢 双端大满贯 / 🟠 状态交错（需合并）/ 🔴 文件双端遗失（建议下架），另有「云端死链」「本地独有」等扩展状态。
- **⚡ 快速刷新**（本地比对）与 **🔍 深度比对**（逐一核对云端真实文件）两级刷新。
- 操作全家桶：**⬇️ 下载选中项**、**⬆️ 上传选中项**（本地版本精准覆盖云端，修复错图/更新内容的利器）、**🔄 智能合并同步**（本地云端互补拼图）、**🧹 清理选中项**、**⬇️ 全量下载**，以及勾选解锁后的 **🗑️ 仅删云端文件 / 🚫 彻底下架**。
- **状态自动逆向同步**：清理后的「仅云端存储」条目，一旦通过下载/合并恢复本地文件，状态会自动跳回「双端大满贯」，无需手动刷新认知。

### 四、常见问题

**Q1：上传失败，提示 `'Repository' object has no attribute 'create_release'`**
A：多为 PyGithub 版本过旧或 Token 权限不足。请先在「设置」一键重装依赖，并确认 Token 勾选了 `repo` / `public_repo`。

**Q2：玩家端看不到我的商品 / 下载 404**
A：依次检查：① Release 是否已 **Publish**（非 Draft）；② **Tag 是否为 `Chisa_Dlc_Store`**（插件端按此 Tag 寻址，自定义 Tag 必 404）；③ 仓库根目录是否有 `index/catalog.json`（同步时勾选「上传 Index」）。

**Q3：玩家端商店名/横幅不是我的装潢**
A：确认已通过「商店元数据装潢」推送 `Chisa_DLC_Metadata.json`（商店名/作者/简介）与 `assets/banner.png`（横幅），并让玩家点一次「🔄 刷新货架」。

**Q4：封面无法加载**
A：封面文件名必须与 DLC ID 一致（如 `fd0001.png`），且已随同步上传到仓库 `covers/` 目录；玩家端可用「🖼️ 橱窗图全量刷新」强制重建。

**Q5：误清理了本地文件怎么办？**
A：完全不必慌——云端数据完好，在云端管理中选中该条目点击「⬇️ 下载选中项」即可完整恢复，「仅云端存储」状态会自动变回「双端大满贯」。

**Q6：可以管理多个仓库吗？**
A：可以。修改仓库地址并保存后即切换，各仓库的本地缓存相互独立；玩家的工坊书架最多可收藏 15 个商店随时切换。

**Q7：能自定义 Release Tag 吗？**
A：工具允许，但**强烈不建议**——插件端固定按 `Chisa_Dlc_Store` Tag 下载商品，自定义 Tag 会导致玩家下载 404。
